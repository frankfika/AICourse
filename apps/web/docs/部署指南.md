# AI Academy 部署指南

AI Academy 由 React/Vite 前端和 NestJS API 组成；生产环境还需要 MySQL、Redis
和兼容 S3 的对象存储。前端不能脱离 API 单独作为完整产品部署。

## 环境要求

- Node.js 20+
- pnpm 11.12+（`corepack enable`）
- MySQL 8、Redis 7、S3/OSS/MinIO
- 反向代理或托管平台，并启用 HTTPS

本地开发可用仓库根目录的 `docker-compose.yml` 启动 MySQL、Redis 和 MinIO；该文件
只提供依赖服务，不会运行 Web 或 API 应用。

## 首次部署

```bash
git clone https://github.com/frankfika/AICourse.git
cd AICourse
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
```

在生产 `.env` 中至少配置：

```env
NODE_ENV=production
DATABASE_URL="mysql://app:strong-password@mysql:3306/ai_academy"
JWT_SECRET="使用 openssl rand -hex 32 生成的随机值"
REDIS_HOST=redis
REDIS_PORT=6379
CORS_ORIGIN="https://academy.example.com"
```

同时为对象存储配置 `STORAGE_*` 变量。不要提交 `.env`，也不要使用示例的 MinIO
账号、JWT 密钥或开发种子账号。

初始化并构建：

```bash
pnpm db:generate
pnpm --filter @ai-academy/api exec prisma migrate deploy
pnpm build
```

API 可通过以下方式启动：

```bash
pnpm start
```

默认监听 `8080` 端口。建议使用 systemd、容器编排或进程管理器保证进程重启和日志采集。

## 反向代理

Web 构建产物位于 `apps/web/dist`。浏览器应与 API 保持同源：将 `/api/` 代理至 API
服务，这样 HttpOnly refresh cookie 才能正常工作。

```nginx
server {
    listen 443 ssl http2;
    server_name academy.example.com;
    root /srv/ai-academy/apps/web/dist;
    index index.html;

    ssl_certificate /etc/letsencrypt/live/academy.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/academy.example.com/privkey.pem;

    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://coresg-normal.trae.ai; font-src 'self' data:; connect-src 'self' https://generativelanguage.googleapis.com; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

如 API 位于其他域名，必须将该 HTTPS 域名加入前端 CSP 的 `connect-src`，并准确设置
`CORS_ORIGIN`；优先采用同源反向代理。

## Vercel / Netlify

可托管 `apps/web`，构建命令为 `pnpm --filter @ai-academy/web build`，输出目录为
`apps/web/dist`。仓库的 `apps/web/vercel.json` 已配置 SPA 回退及静态响应安全头。

托管前端时仍需部署 API 和依赖服务，并配置同源 `/api` 反向代理。若平台无法代理 API，
需设置 `VITE_API_BASE_URL=https://api.example.com`，并同步调整 CSP、CORS 和 cookie 的
SameSite/Domain 策略；这不是默认推荐方案。

## 上线检查

```bash
pnpm check
pnpm e2e
pnpm audit --registry=https://registry.npmjs.org --audit-level=critical
```

上线前还应确认：数据库迁移已应用、Redis 与对象存储凭据为生产凭据、HTTPS 与 CORS
已配置、OAuth 回调地址为 HTTPS、支付入口在真实支付和 webhook 验签完成前保持关闭。

## 更新与回滚

每次发布前先执行上述检查，再依次部署 API、执行迁移、发布前端。迁移应保持向后兼容，
并在发布前备份数据库；发现异常时优先回滚应用版本，避免直接回退已经执行的数据库迁移。
