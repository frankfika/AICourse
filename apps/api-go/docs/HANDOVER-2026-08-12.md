## 5. 关键 lesson (接手时必须知道)

### 5.1 绝对不能并发跑 dockertest test

写进 agent memory 了:**Mac dev box 撑不住 2+ 个 dockertest 进程**。每个 dockertest test = 1 个 MySQL container + 1 个 go test, 吃 2-3GB RAM。host load > 8 MySQL 启动 8s → 60s+, MaxWait 300s 都不够。

**正确做法**:
- 同时只能跑 1 个 dockertest test 进程
- 每跑完一个 module, **必须** `docker rm -f` 掉 container
- Frank 电脑之前被卡就是因为 3 个 agent + 我同时跑, load 飙到 12

诊断信号:
- `packets.go:58 unexpected EOF` 大量出现 = MySQL 启动中被打断
- `reached retry deadline: dial tcp ... connection refused` = MaxWait 不够
- `mysql never came up` = 同样的问题

### 5.2 测试代码层的小坑 (写新 test 时注意)

- `insertUserDirect` 返回 userID, **`loginAs` 接受 email 不是 ID** (我之前踩过)
- counter/int 字段优先用 `*int32` 不用 `int32 + omitempty` (0 时字段会消失)
- `pool.MaxWait = 180 * time.Second` 是 hard 必加, 不写默认 60s
- Fiber route 顺序 = match priority, static path 在 `/:param` 之前
- hackathons sub-test (judges/sponsors/teams/submissions) 不直接用 dockertest, 走父 setup

### 5.3 dockertest 已修的 MaxWait 名单 (不要重复加)

7 个文件已设 MaxWait, 接手的你别再加:
- admin_test.go (300s), audit_test.go (300s), cms_test.go (300s)
- enterprise_test.go (90s), expertises_test.go (300s)
- hackathons_test.go (180s), urlimport_test.go (90s)
